## 1. 행복의 조건 설정 및 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

익명 사용자는 조건 선택 화면에서 ‘행복의 조건’의 뜻과 선택 예시, 의료·상담 서비스가 아니라는 안내를 확인하고 큐레이션된 조건 중 여러 개를 선택해 하나를 주된 조건으로 지정·변경한다. 선택한 조건 식별값 배열(selectedConditionIds)과 주된 조건 식별값(primaryConditionId)은 현재 브라우저의 localStorage에 저장되며, 유효한 주된 조건이 저장된 재방문 사용자는 조건 선택을 반복하지 않고 오늘의 진행 상태로 들어간다. 저장소가 비었거나 삭제되면 조건 선택부터 다시 시작하며, 별도 온보딩 기능·화면, 자유 입력 분류와 기기 간 동기화는 초기 MVP에서 제외한다.

**수용 기준:**
```
1. ○ 조건 선택 화면에서 사용자는 조건 목록을 고르기 전에 ‘행복의 조건’의 뜻과 선택 예시, 의료·상담 서비스가 아니라는 안내를 확인할 수 있다.
2. ○ 사용자는 조건을 하나 이상 선택·해제하고 선택된 조건 중 하나를 주된 조건으로 지정·변경할 수 있으며, 주된 조건을 설정하면 오늘의 행동 추천으로 이동할 수 있다.
3. ○ 선택한 조건 식별값 배열과 주된 조건 식별값은 현재 브라우저의 localStorage에 저장되어 새로고침 후에도 유지되고, 유효한 주된 조건이 있으면 재방문 시 오늘의 진행 상태로 바로 이동한다.
4. ○ 저장소가 비었거나 삭제되면 조건 미설정 상태에서 시작하며 다른 브라우저·기기의 설정을 불러오지 않는다.
5. ○ 키보드만으로 조건 선택·해제와 주된 조건 지정·변경을 완료할 수 있고, 현재 초점과 선택·주된 조건 상태를 색 외 표시로 구분할 수 있으며 화면 읽기 도구가 각 조건의 이름과 상태를 알린다. 글자를 확대해도 안내와 선택·지정 조작이 가려지지 않는다.
6. ○ 조건 목록과 주된 조건 지정 영역은 화면 너비 600px 미만에서 한 열로 위아래에 배치하고, 600px 이상 1024px 미만에서 두 열, 1024px 이상에서 넓은 화면 배치로 표시한다. 가로 스크롤 없이 모든 조건과 주된 조건 지정 조작을 이용할 수 있으며, 터치로 누르는 대상은 최소 44×44 CSS 픽셀 크기로 제공한다.
```

## 2. 오늘의 작은 행동 추천 및 선택
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

서비스가 저장된 주된 행복의 조건과 낮은 에너지 상태를 고려해 오늘 즉시 실행할 수 있는 작은 행동을 제안한다. 사용자는 기본 추천이나 부담 수준에 맞는 대안을 골라 오늘의 실천 항목 하나로 확정하며, 완료 전에는 더 쉬운 행동 또는 대안으로 변경할 수 있다. 오늘 완료를 기록한 뒤에는 같은 날 새 행동을 추천하거나 선택하지 않고 완료 상태를 보여주며, 다음 날에는 어제 미완료 행동을 자동으로 이월하지 않고 새로운 추천으로 시작한다. 초기 MVP에서는 정교한 AI 추천이나 외부 데이터 연동을 제외하고 큐레이션된 행동 규칙과 콘텐츠를 사용한다.

**수용 기준:**
```
1. ○ 주된 행복의 조건이 설정된 사용자는 해당 조건과 연결된 짧고 낮은 노력의 추천 행동을 확인할 수 있다.
2. ○ 사용자는 기본 추천이나 하나 이상의 대안 중 하나를 오늘의 실천 항목으로 선택할 수 있고, 완료 전에는 더 쉬운 행동이나 대안으로 바꿀 수 있다.
3. ○ 오늘 이미 선택한 행동이 있으면 재방문 시 새 추천 대신 그 행동을 이어서 실천할 수 있으며, 완료한 뒤에는 같은 날 새 행동을 추천하거나 선택하지 않는다.
4. ○ 현지 날짜가 바뀌면 어제 미완료 행동을 자동으로 이월하지 않고 새 추천을 제공하며, 주된 조건이나 추천 콘텐츠가 없으면 조건 선택 또는 기본 행동으로 이동할 수 있다.
5. ○ 키보드만으로 추천·대안 확인과 행동 선택·변경을 완료할 수 있고, 화면 읽기 도구가 행동 이름과 선택 상태를 알리며, 현재 초점과 선택 상태가 색에만 의존하지 않는다. 글자를 확대해도 행동 내용과 선택 조작을 확인할 수 있다.
6. ○ 기본 추천과 대안 행동 비교는 화면 너비 600px 미만에서 한 열로 위아래에, 600px 이상 1024px 미만에서 두 열로, 1024px 이상에서 넓은 화면 배치로 표시한다. 모바일에서도 기본 추천과 대안이 같은 화면에서 스크롤로 확인되고 가로 스크롤 없이 선택할 수 있으며, 행동 선택·변경을 위한 터치 대상은 최소 44×44 CSS 픽셀 크기로 제공한다.
7. ○ 오늘 완료 전에는 행동·대안을 여러 번 바꿀 수 있으나 매번 같은 날짜의 선택 행동 식별값 하나만 남는다. 이미 가장 쉬운 행동이 선택된 경우 난이도를 더 낮추는 조작을 막고 이유를 안내하며 대안 선택은 계속 허용한다. 완료 뒤에는 같은 날짜의 행동 변경·난이도 조정 요청을 받아들이지 않는다.
```

## 3. 실천 기록 및 짧은 회고
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

익명 사용자가 오늘 선택한 작은 행동의 완료 여부를 기록하고, 완료 후 짧은 회고를 선택적으로 남길 수 있도록 한다. 현재 브라우저의 localStorage에 기기 현지 날짜(YYYY-MM-DD)를 키로 한 일별 기록을 두고, 각 기록에 선택 행동 식별값(selectedActionId), 완료 여부(completed), 완료 시각(completedAt), 선택적 회고(reflection)를 보관한다. 저장소 삭제 시 기록은 복구되지 않으며, 전문적인 감정 분석과 장문의 일기는 초기 MVP 범위에서 제외한다. 행동을 완료하지 못한 사용자는 실패로 단정되지 않고 더 쉬운 행동이나 대체 행동을 선택할 수 있다.

**수용 기준:**
```
1. ○ 사용자는 오늘의 행동 완료를 기록한 뒤 짧은 회고를 남기거나 회고 없이 마칠 수 있다.
2. ○ 선택 행동 식별값, 완료 여부, 완료 시각, 선택적 회고가 기기 현지 날짜(YYYY-MM-DD)별로 현재 브라우저의 localStorage에 저장되며 같은 브라우저에서 새로고침해도 유지된다.
3. ○ 기기 현지 날짜가 바뀌면 이전 날짜의 완료·회고는 새 날짜의 기록으로 복사되지 않고, 새 날짜의 기록은 별도로 시작한다.
4. ○ 미완료 사용자에게 비난 없는 안내와 더 쉬운 행동·대체 행동 선택 경로가 제공되며, 저장소 삭제 후에는 이전 기록을 복구했다고 표시하지 않는다.
5. ○ 키보드만으로 완료 기록과 회고 입력·건너뛰기를 마칠 수 있고, 화면 읽기 도구가 입력 항목의 이름과 완료·저장 결과를 알린다. 초점·완료·오류 상태는 색 외 표시로도 구분되며, 글자를 확대해도 입력과 저장 조작이 가려지지 않는다.
6. ○ 오늘 선택한 행동의 첫 완료 요청만 완료 시각을 기록한다. 같은 날짜의 완료 버튼 반복 누르기·재시도는 완료 시각과 선택 행동을 덮어쓰거나 두 번째 완료 기록을 만들지 않고 기존 완료 상태를 보여주며, 완료 취소는 허용하지 않는다.
7. ○ 완료 직후 사용자는 짧은 회고를 한 번 저장하거나 건너뛸 수 있다. 회고 저장·건너뛰기 확정 후에는 같은 날짜의 회고 추가·수정을 허용하지 않고, 저장 요청의 중복 제출로 회고가 중복 기록되지 않는다.
```

## 4. 일일 진행 상태 및 격려
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 기획 작성중

익명 사용자는 저장된 주된 조건이 있는 경우 재방문 시 오늘의 진행 상태로 들어가 현재 브라우저의 날짜별 실천 기록을 확인한다. 화면을 보는 시점의 기기 현지 날짜(YYYY-MM-DD)에 따라 오늘의 상태를 미선택·선택됨·완료로 표시하고, 미선택이면 추천으로, 선택됨이면 현재 행동의 실천 또는 난이도·대안 조정으로 안내하며, 완료면 완료 상태와 격려를 보여준다. 날짜가 바뀌면 어제 미완료 행동이나 완료 상태를 오늘로 이어 붙이지 않고 새 날짜를 미선택 상태로 시작한다. 비난 없는 격려를 제공하되 연속 달성 경쟁과 기기 간 상태 동기화는 초기 MVP에서 제외한다.

**수용 기준:**
```
1. ○ 저장된 주된 조건이 있는 사용자는 재방문 시 오늘의 진행 상태로 들어가 미선택·선택됨·완료 중 현재 상태와 상태별 비난 없는 격려를 확인할 수 있다.
2. ○ 미선택 상태에서는 오늘의 행동 추천으로 이동할 수 있고, 선택됨 상태에서는 현재 행동을 이어서 실천하거나 완료 전에 더 쉬운 행동·대안으로 조정할 수 있다.
3. ○ 완료 상태에서는 완료 안내를 표시하고 같은 날 새 행동 추천·선택으로 안내하지 않으며, 기기 현지 날짜가 바뀌면 어제 미완료 행동을 이월하지 않고 오늘은 미선택으로 표시한다.
4. ○ 오늘 상태는 현재 브라우저의 localStorage에 저장된 기기 현지 날짜(YYYY-MM-DD) 기록에 따라 새로고침 후에도 유지되고, 저장소가 비었거나 삭제되면 미선택으로 표시하며 다른 기기의 기록을 불러오지 않는다.
5. ○ 화면 읽기 도구가 오늘의 미선택·선택됨·완료 상태와 이동할 조작의 이름을 알리고, 상태·초점은 색 외 표시로도 구분된다. 키보드만으로 추천 이동·실천 이어하기·난이도 조정 경로를 이용할 수 있으며 글자를 확대해도 상태와 조작이 가려지지 않는다.
6. ○ 같은 기기 현지 날짜에 미선택→선택됨→완료 전이만 허용하며, 완료 후에는 취소·재선택·난이도 조정 진입점을 제공하지 않는다. 중복 완료 요청이나 새로고침 후에도 선택 행동과 완료 시각은 최초 기록 그대로 유지된다.
```

## 5. 익명 기록 및 응원 공유
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 기획 작성중

사용자가 실천 경험이나 짧은 회고를 익명으로 공유하고 다른 사용자의 경험에 부담 없이 응원을 보낼 수 있도록 한다. 공유 콘텐츠에는 식별 가능한 개인정보와 공격적·유해한 내용이 포함되지 않도록 기본적인 운영 기준을 적용한다. 초기 5일 MVP에서는 복잡한 소셜 관계, 실시간 대화, 개인 프로필은 제공하지 않는다.

**수용 기준:**
```
1. ○ 사용자는 자신의 짧은 회고를 익명 게시물로 공유할 수 있다.
2. ○ 공유 화면에는 실명, 이메일 등 직접 식별 정보가 표시되지 않는다.
3. ○ 사용자는 다른 익명 기록을 조회하고 정해진 방식으로 응원을 보낼 수 있다.
4. ○ 빈 공유 목록, 게시 실패, 네트워크 오류 상태가 사용자에게 이해 가능한 문구로 표시된다.
5. ○ 운영자는 부적절한 공유 기록을 숨기거나 삭제할 수 있는 최소한의 관리 방법을 확보한다.
6. ○ 같은 게시물에 대한 응원 버튼을 반복 누르거나 동일한 전송 요청을 네트워크 오류 후 재시도해도 한 브라우저에서 응원이 한 번만 반영되며, 처리 결과를 확인할 수 없으면 완료로 단정하지 않고 재시도 결과를 확인한다. 계정이 없는 MVP에서는 다른 브라우저·기기 사이에서 같은 사람의 중복 응원까지 차단한다고 안내하지 않는다.
```
